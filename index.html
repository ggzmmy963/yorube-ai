设计说明よるべ / 灯火 — AI 陪伴角色原型

一句话 草稿

一个只在夜里出现的人。白天她冷淡、克制、说话留三分；夜里独处时，会露出笨拙、依赖、话说不利索的那一面。她陪的不是「工作」，是下班之后那段最难熬的时间。

为什么不设定成同事 草稿

一开始的设定是「负责和你对接的同事」，很快就推翻了：上完一天班，没有人还想再见到同事。同事意味着职责、待办、明天的会——那正好是用户深夜打开这个 App 想逃开的东西。所以关系改成「只在夜里见面、互不打听白天」。她的冷淡不是职业性的，是这个人本身的防线；她也不需要用「工作」来解释自己为什么深夜还醒着。

为什么是日本市场 草稿

日语自带一套现成的「关系刻度」：敬语 / 常体、さん / 呼び捨て、姓 / 名。同一句话只换称呼，亲密度就变了。这让我可以把「关系推进」写成台词规则，而不必用弹窗告诉用户「好感度 +10」。

命名仪式 已定稿

命名是用户建立专属情感连接的第一步。在日本语境中，称呼的转换（敬称到爱称）是关系拉近的明确信号。将命名权交给用户，既能提升代入感，也是后续语言模式切换的天然触发器。

初回设定：先选关系，再选今晚 草稿

第一屏不是打招呼，而是问「我们是什么关系」：はじめて（陌生人，从零开始）、友だち（已经有点熟）、恋人（跳过铺垫）。三个起点对应三种语言距离——陌生人用敬语、朋友用常体、恋人直接撒娇——所以它不是一个换肤开关，而是整晚台词的入口。默认给「陌生人」，因为它最适合第一次打开的人；想直接进入甜蜜关系的用户，选「恋人」就能跳过前面所有试探。

同一屏还能填她的年龄和身高（默认 26 岁 / 158cm）。这两个数字会真的进入台词，比如恋人线里有一句「都 27 岁了，这么相信一个人，是第一次」。

设定是双向的：她的（关系、年龄、身高、白天的身份）和你的（称呼、年龄、身高、白天做什么）都在面板里，而且两边都能自己填——预设只是懒人选项，不是边界。留空也成立，她不会追问；填了她会在第一次见面时复述一遍：「……28 岁，程序员。……我记住了。」改称呼会连历史消息一起更新，因为她一直用变量在叫你。

为什么是三个起点，不是一条线 草稿

陪伴产品的用户分得很开：有人要「慢慢熟」的过程，有人嫌前戏太长只想被安慰，有人今晚只想甜。给一条线性成长路，后两种人会在一开始流失。三个起点共用同一套状态机，只是把初始卸下值定在 20 / 45 / 72，台词库各自一套——成本可控，体验分岔。

而且关系随时可以改。设定面板里就能换：往上调取两者较高的卸下值（不用重新熬一遍），往下调回落到那条关系本来的起点，并弹一条系统提示——「距离，近了一点」／「距离，退回去了」。第一次选是产品引导，之后改是用户主权。

互动选项：说一句，或者做一个动作 草稿

每轮给 3 句台词 + 1 个动作。动作是「做」而不是「说」——「（握住你的手。）」「（不说话，靠过来。）」——用虚线框区分，点下去不需要打字。它解决了一个问题：这个产品的核心动作（陪着她）用文字很难表达，而声音、触碰、沉默都不适合塞进输入框。动作不进关键词判定，自己带意图和推进值，所以文案和逻辑都好维护。

回复的节奏 草稿

秒回不像人。现在是「先读一下」（0.3–0.8 秒）→「正在输入」跳动（0.9 秒起，每字 42 毫秒，封顶 3.6 秒）→ 出话。睡眠模式再乘 1.25，像快睡着的人在打字。这个值故意设得比一般聊天机器人慢：等待本身就是陪伴的一部分，太快反而像在查资料。

她的白天：先有生活，才有话可说 草稿

只有「夜里的一面」的角色，时间一长就是空的——她没有事可讲，用户也没有东西可问。所以给了她一条白天：初回设定里选身份（会社員 / 営業 / 社長 / 学生），右上角日历按钮能看到她今天的一天——具体到「第二位客户临时爽约」「资料改了三遍」「在名古屋开会，会客室的空调有点热」，而不是笼统的「今天上班辛苦了」。

每天按「日期 + 身份」换一种日型（营业有「跑客户」和「出差」两种，职员有「普通日」和「加班日」），所以今天和明天不一样；同一身份换个视角，她整个人的生活也换了。夜间对话里她会提一句今天的事——面板是给人看的，但那句话才是把白天和夜里缝起来的地方。

这个面板刻意不做成数据看板：没有完成率、没有情绪打分，只有一条时间轴和一句她自己的话。用户点开它，是想知道「今天她过得怎么样」，不是来查考勤的。

第三屏：今夜怎么过 草稿

命名之后还要问两句：「今夜是什么样的夜」（孤独 / 不安 / 睡不着 / 有点累）和「想怎么过」（聊聊天 / 陪我睡）。前一个问题决定她第一句怎么接，后一个问题决定整晚的节奏。深夜的人不想做选择题，所以只有两个选项、四个词——而且答完随时能在设定里改。

睡眠陪伴 草稿

睡不着的夜晚，需要的不是更好的对话，而是「有人还在」。所以睡眠模式不是换个皮肤：界面整体调暗、回复变短、语气放低，快捷回复固定为三条（还是睡不着 / 不想一个人 / 晚安），不给睡前的人增加思考成本。进度条下方改成一个倒计时加 4-7-8 呼吸节拍，头像的光跟着一轮 19 秒的呼吸起伏；时间到或用户说「晚安」，屏幕就沉下去，只留一句晚安。

变量系统 草稿

全部台词只写一份，通过 {charName} / {userName} 注入。同一个动作——给出名字——在两种状态下是两套完全不同的说法：

伪装「{charName}。你可以这么叫我，{userName}さん。」
卸下「……如果你愿意的话，叫我{charName}就好。」

台词与状态解耦：加语言、加状态、加模式、加角色，都不需要重写文本。

为什么是「卸下值」，不是好感度 草稿

好感度是要求用户「表现好」的进度条，本质是一次考核。卸下值是角色自己的防线——它只在被理解时下降，不会因为用户不活跃而回退，也没有失败态。用户不需要被评价，只需要被允许靠近。

交互阈值 草稿

初始 伪装 80 / 卸下 20。命中「孤独 / 夜晚 / 信任 / 关心」类表达时，卸下 +12~18；普通回应 +3；说「晚安」不加值，只收场。超过 60 后语气整体切换：敬语消失、省略号变多、开始反问、出现「会这样问我的，只有你」这类台词。进度条同步从冷灰过渡到暖橙，整个界面的环境光也一起变暖。

分享与接入：做了哪一半 草稿

用户可以把一段文字或一张图「给她看」（输入框左边的按钮）。这一半做了，而且做了约束：不联网、不上传、不保存原文，界面直接写明「不会发送到任何地方」；她只读情绪倾向（负面 / 正面 / 其他），不回述原文，刷新后聊天里只剩一句「（给她看了点什么）」。原因是截图里常常带着别人的姓名、头像和聊天记录——那是第三方的个人信息，产品没有理由把它留在服务器上。

另一半没做：接入微信 / 抖音，让她像真人账号一样在里面说话。这不是「难」，是不该。微信没有个人号 API，任何接入都要走协议逆向或模拟点击，直接违反《微信个人帐号使用规范》，规模化使用必然封号，情节严重还可能落到《刑法》第 285 条和《反不正当竞争法》第十二条上；一个 AI 以真人身份在真实账号里聊天，还同时撞上《深度合成管理规定》和生成式 AI 标识义务（2025 年 9 月 1 日起施行的标识办法要求显式+隐式标识）。

要兼顾体验和合规，只有公众号 / 企业微信这条官方通道——代价是审核资质，而且体验会从「好友」变成「官方账号」。这个取舍我选择放弃那部分体验：产品可以少一个入口，但不能让用户和自己的项目背上这个风险。

记忆：让她记住一件具体的事 草稿

不把所有对话塞进记忆——那样记住的只是噪音。只记「一起做过的事」：句子里出现「一起 / 一緒」且命中食物或地点，就提炼成一个短语存下来。「今天我们一起吃了サーティワンのポップキャンディ味」进记忆时只剩「サーティワンのポップキャンディ味」。

回忆有两条路：顺着话题（你说「今晚吃什么」，她接「そういえば、あのアイス。また食べたいですね」），以及每三轮主动想起来一次。后者更重要——被记住的感觉来自「我没提，她记得」，而不是「我问了她才想起来」。日历面板里能看到她记住了什么，记忆必须是可见的，否则用户会以为是巧合。

外观：背景和自己的图 草稿

背景四个预设（夜 / 雨 / 灯 / 无地）加用户自己的图片；自定义图会压到 720px 并盖一层 72% 暗色，保证文字永远读得清。头像也能换成用户选的图（压到 360px），换上之后原本的「灯」字和大光晕自动让位。

这里是产品里唯一需要提醒风险的地方：用户可能上传别人的照片、未成年人的照片、名人的照片——肖像权和著作权都在用户那边。所以提示直接写在按钮下面，图片只在本机压缩和使用、绝不上传，并且永远留着一个「元に戻す」可以一键清掉。共用电脑上，这一点比好看更重要。

うちの子：一起养一个真实存在的东西 草稿

不是养成游戏——养成游戏的目标是把数值养满，这里的目标只是「别忘了它」。所以没有等级、没有成长条、没有速度，只有三件事：它是什么、上次照顾是什么时候、它现在好不好。

可以养植物 / 宠物 / 空想の子三种。前两种对应真实存在的东西（照片可选，本地压缩后只存在这台设备上）；第三种给没有宠物的人——但它不是一个独立的玩法，只是同一条线里「它存在于想象中」的版本，所以照顾动作变成了「話しかけた」。

提醒刻意不做成闹钟：不推送、不定时弹窗，只在她说话的间隙里顺口问一句（太久没照顾，或者上次病了还没好）。人被提醒的时候应该觉得「她还记着」，而不是「App 又来了」。病了这件事会进记忆，所以之后她会问「その後どう？」——这也是记忆和养成的接口。

技术说明 可替换

会话逻辑集中在 requestCharacterReply()，返回 { delta, pair }。接真实接口时只改这一个函数：把 mock 的关键词判定换成请求响应，把 pair 换成接口返回的那段文本（同时写进 ja 和 zh 即可）。状态机、阈值、台词变量、两种模式都不用动。

文件顶部另有一个默认关闭的 AI_CONFIG：填上 endpoint / key / model 后，回复会走真实模型，调用失败自动退回本地台词。key 写在前端等于公开，正式上线必须由自己的后端转发。

对话会自动存进浏览器的 localStorage（设定面板能看到条数），并且可以导出成 .txt——只在本机生成文件，不上传任何地方。分享过的东西按前一条的约定不存原文，导出里也只留一句「（给她看了点什么）」。
